# ICS 배포 체크리스트 (사이트 정체 확인)

**목적 하나**: ICS 설정을 **엉뚱한 사이트에 배포한 것**을 자료를 한 장이라도 찍기 전에 잡는다.

## 왜 이 문서가 있나

`[node] site` 한 줄이 사이트 코드 → 좌표 → 관측일 경계 → 파일명까지 전부 끌고 간다 (D-011 · D-014). 그 한 줄이 틀리면 **아무 오류 메시지 없이** 전부 틀린다:

| 틀리는 것 | 증상 |
| --- | --- |
| 파일명 `<SITE>` prefix | 아카이브에 다른 사이트 이름으로 영구히 박힌다 |
| `OBSERVAT` · `SITEID` · `TELESCOP` | 헤더가 다른 관측소를 주장한다 |
| `LATITUDE`/`LONGITUD`/`ELEVATIO` | **겉보기엔 유효한 좌표**라 아무도 의심하지 않는다 |
| 관측일 경계 | 야간 묶음이 갈라진다 (사이트마다 경계가 다르다) |

converter 의 교차검증(파일명 `<SITE>` ↔ `OBSERVAT`)은 **둘 다 우리 설정에서 나오므로 이걸 못 잡는다.** 사후에 자료를 보면 알 수 있지만 그때는 이미 아카이브에 들어가 있다 — 그래서 **기동 순간에 사람이 확인하는 것**이 유일하게 값싼 방어다.

## 기동할 때 (매번)

ICS 를 띄우면 로그 맨 앞에 정체 블록이 한 번 찍힌다. **이걸 읽고 넘어간다.**

```text
==========================================================================
 사이트 정체 -- 배포가 맞는지 여기서 확인하세요
--------------------------------------------------------------------------
 사이트         KMTC   (OBSERVAT=CTIO)
 판정 근거      192.168.14.109 in 192.168.14.0/24
 TELESCOP       KMTNet 1.6m #1
 위치           lat -30:10:01.84   lon +70:48:14.39 (서경)   elev 2140 m
 관측일 경계    UT 16:30   -- 파일명 <YYYYMMDD> 가 이 경계로 갈린다
 파일명 예시    KMTC.20260813.001234.MK.fits
 data_dir       /home/.../icsdata
 EXPNUM         다음 001234   (기록 ~/AICS/Config/ics_sim.expnum)
 backend        archon   ->  DATASRC=ARCHON
==========================================================================
```

확인할 것 — **전부 이 표 안에서 끝난다:**

- [ ] **`사이트`** 가 지금 서 있는 관측소인가
- [ ] **`파일명 예시`** 를 이 이름으로 아카이브에 넣어도 되는가 (제일 빠른 확인)
- [ ] **`TELESCOP`** 번호가 맞는가 (`#1`=CTIO · `#2`=SAAO · `#3`=SSO)
- [ ] **`위치`** 좌표가 이 관측소인가. `lon` 은 **서경**이다 — `339:11:22`(SAAO)·`210:56:08`(SSO)이 정상이고, 동경으로 "고치면" 부호가 뒤집힌다
- [ ] **`관측일 경계`** 가 맞는가 (CTIO UT 16:30 · SAAO UT 10:30 · SSO UT 01:30 — 셋 다 현지 12:30)
- [ ] **`backend`/`DATASRC`** — 실관측이면 `ARCHON` 이어야 한다. `SIM` 이면 시뮬 프레임이 아카이브로 흘러간다
- [ ] **`EXPNUM`** 이 되돌아가지 않았는가 (되돌아가면 이름이 겹쳐 `clash/` 로 격리된다)
- [ ] 블록 위아래에 **경고(WARNING)가 없는가**

## 경고가 떴을 때

| 경고 | 뜻 | 할 일 |
| --- | --- | --- |
| `사이트 판정이 설정과 다르다` | 호스트 IP 로 판정한 사이트와 ini 의 `site` 가 다르다. **판정을 따라 파일명이 정해진다** | 현장 장비면 ini 가 잘못 배포된 것이거나 **기기망 NIC 이 내려간 것**이다. 벤치면 `[node] site = kasi` 로 맞춰 두면 조용해진다 |
| `사이트가 KMTK(KASI)로 판정됐는데 백엔드가 실물` | **실화소가 `KMTK.…` 로 저장된다** | 자료를 찍기 전에 멈춘다. 호스트가 사이트 대역에 없다는 뜻이다 |
| `TC 의 TELID 가 우리 사이트 판정과 다르다` | `pctcs.ini` 의 `FITS_TelID` 가 다르다. **서로 다른 값마다 한 번씩만** 뜨므로, 조용해졌다고 해결된 것은 아니다 | 어느 쪽이 잘못 배포됐는지 확인. 파일명은 우리 판정을 따른다 |
| `TC 가 TELID=KMTN 을 보냈다` | pctcs 의 `FITS_TELID` 가 **미설정 기본값**이다 | `pctcs.ini` 의 `FITS_TELID` 를 채운다. 우리 파일명에는 영향 없다 |
| `사이트 … 의 측지값이 없다` | `[site.<코드>]` 가 비어 있다 | 좌표가 sentinel 로 실린다. ini 를 채운다 |

## 사이트를 옮겨 배포할 때

**`[node] site` 한 줄만 고친다.** 좌표·경계·파일명이 따라온다 — `[site.ctio]`/`[site.saao]`/`[site.sso]` 가 ini 안에 다 들어 있다.

그 다음 **한 번 띄워 배너를 확인한다.** IP 판정이 ini 를 이기므로, 배포가 어긋났으면 배너와 경고에 바로 드러난다.

## 망 구성이 바뀌면

사이트 판정은 `/24` 대역에 매여 있다:

```text
192.168.14.x → CTIO(KMTC)    192.168.13.x → SAAO(KMTS)    192.168.15.x → SSO(KMTA)
그 밖 전부   → KASI(KMTK)
```

> ⚠️ **신규 CEU 망이 이 대역을 그대로 쓴다는 것은 구두 확인(2026-08-13)뿐이고, 저장소에 CEU 망 문서가 없다.** 대역이 바뀌면 `ics_sim/ics_sim/siteid.py` 의 `SITE_SUBNETS` 와 이 문서를 **함께** 고쳐야 한다. 안 고치면 실사이트가 벤치로 판정돼 **실자료가 `KMTK` 이름으로** 저장된다.
>
> 호스트의 마지막 옥텟은 **일부러 보지 않는다.** 레거시의 역할-옥텟 지도는 신규에서 무효다 — 머신 7대가 2대로 통합됐다(DevNote 9.1). 인터페이스 netmask 도 쓰지 않는다 — 13/14/15 가 인접해서 누군가 `/22` 로 잡으면 세 사이트가 한 망으로 합쳐진다.
