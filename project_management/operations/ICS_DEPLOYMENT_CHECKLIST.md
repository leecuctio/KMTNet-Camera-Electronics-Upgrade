# ICS 배포 체크리스트 (사이트 정체 확인)

**목적 하나**: ICS 설정을 **엉뚱한 사이트에 배포한 것**을 자료를 한 장이라도 찍기 전에 잡는다.

> ⚠️ **개정 (2026-08-26, `ics-archon-v1.0-build`)** — 사이트 판별이 **`[node] observatory` 한 줄**로 바뀌었고 **호스트 IP 판정(D-015)은 폐지**됐다 (목 확정 2026-08-24, DevNote 11.27). 사이트 코드 넷째 자리도 `KMTT`/`TESTBED` → **`KMTK`/`KASI`** 다 (D-017). 아래 본문은 그 기준으로 고쳤다.

## 왜 이 문서가 있나

**`[node] observatory` 한 줄**이 사이트 코드 → 좌표 → 관측일 경계 → 파일명 → `TELESCOP`·`FPAID` 까지 전부 끌고 간다 (D-011 · D-014 · D-017). 그 한 줄이 틀리면 **아무 오류 메시지 없이** 전부 틀린다:

| 틀리는 것 | 증상 |
| --- | --- |
| 파일명 `<SITE>` prefix | 아카이브에 다른 사이트 이름으로 영구히 박힌다 |
| `OBSERVAT` · `ORIGIN` · `TELESCOP` · `FPAID` | 헤더가 다른 관측소·다른 검출기 조립체를 주장한다 |
| `LATITUDE`/`LONGITUD`/`ELEVATIO` | **겉보기엔 유효한 좌표**라 아무도 의심하지 않는다 |
| 관측일 경계 | 야간 묶음이 갈라진다 (사이트마다 경계가 다르다) |

converter 의 교차검증(파일명 `<SITE>` ↔ `OBSERVAT`)은 **둘 다 우리 설정에서 나오므로 이걸 못 잡는다.** 사후에 자료를 보면 알 수 있지만 그때는 이미 아카이브에 들어가 있다 — 그래서 **기동 순간에 사람이 확인하는 것**이 유일하게 값싼 방어다.

⚠️ **모르는 값은 기동을 거부한다** (오타·구판 값). 조용히 KASI 로 떨어뜨리지 않는다 — 그 관대함이 관측소 자료를 실험실 이름으로 아카이브에 들여보내는 경로였다. 그래서 **구판 `observatory = TESTBED` 로 설치된 사본은 기동하지 않는다**: `KASI` 로 고치고 `[site.testbed]` 절도 `[site.kasi]` 로 바꿔야 한다.

## 기동할 때 (매번)

ICS 를 띄우면 로그 맨 앞에 정체 블록이 한 번 찍힌다. **이걸 읽고 넘어간다.**

```text
==========================================================================
 사이트 정체 -- 배포가 맞는지 여기서 확인하세요
--------------------------------------------------------------------------
 사이트         KMTC   (OBSERVAT=CTIO)
 근거           [node] observatory=CTIO
 TELESCOP       KMTNet 1.6m #1
 FPAID          FPA#2
 위치           lat -30:10:01.84   lon +70:48:14.39 (서경)   elev 2140 m
 관측일 경계    UT 16:30   -- 파일명 <YYYYMMDD> 가 이 경계로 갈린다
 파일명 예시    KMTC.20260813.001234.MK.fits
 data_dir       /home/.../icsdata
 EXPNUM         다음 001234   (기록 ~/AIC/Config/ics_sim.expnum)
 backend        archon   ->  DATASRC=ARCHON
==========================================================================
```

확인할 것 — **전부 이 표 안에서 끝난다:**

- [ ] **`사이트`** 가 지금 서 있는 관측소인가
- [ ] **`파일명 예시`** 를 이 이름으로 아카이브에 넣어도 되는가 (제일 빠른 확인)
- [ ] **`TELESCOP`** 번호가 맞는가 (`#1`=CTIO · `#2`=SAAO · `#3`=SSO · `#0`=KASI)
- [ ] **`FPAID`** 가 맞는가 (CTIO `FPA#2` · SSO `FPA#1` · SAAO `FPA#3` · KASI `FPA#0`). ⚠️ **망원경 번호와 일부러 다르다** — 관측소 셋 모두 어긋난다. 맞추면 검출기 귀속이 틀어진다 (D-017 항목 6, raw spec 5.3.1절)
- [ ] **`위치`** 좌표가 이 관측소인가. `lon` 은 **서경**이다 — `339:11:22`(SAAO)·`210:56:08`(SSO)이 정상이고, 동경으로 "고치면" 부호가 뒤집힌다
- [ ] **`관측일 경계`** 가 맞는가 (CTIO UT 16:30 · SAAO UT 10:30 · SSO UT 01:30 — 셋 다 현지 12:30. KASI 는 보정 0)
- [ ] **`backend`/`DATASRC`** — 실관측이면 `ARCHON` 이어야 한다. `SIM` 이면 시뮬 프레임이 아카이브로 흘러간다
- [ ] **`EXPNUM`** 이 되돌아가지 않았는가. 겹치면 **번호를 증가시켜 저장**하고, **`FILENAME` 의 `.MK`/`.NT` 꼬리를 뗀 값 ≠ `EXPID`** 로 남는다 (D-016 — 구 `clash/` 격리는 폐지 / **D-019 로 신호 개정** — 구 `FILENAME ≠ ORIGNAME` 직접 비교). 번호 공간은 `000000`–`999999` (D-018)
- [ ] 블록 위아래에 **경고(WARNING)가 없는가**

## 경고가 떴을 때

| 경고 | 뜻 | 할 일 |
| --- | --- | --- |
| `OBSERVATORY=… 를 모르겠다` (**기동 거부**) | `[node] observatory` 가 `CTIO`/`SSO`/`SAAO`/`KASI` 밖이다. 구판의 `TESTBED` 가 그대로 남아 있는 경우가 대부분이다 | 넷 중 하나로 고친다. `[site.testbed]` 절이 있으면 `[site.kasi]` 로 함께 바꾼다 |
| `사이트가 KMTK(KASI)인데 백엔드가 실물` | **실화소가 `KMTK.…` 로 저장된다** | 자료를 찍기 전에 멈춘다. 관측소 장비라면 `[node] observatory` 가 `KASI` 로 남아 있는 것이다 |
| `TC 의 TELID 가 우리 사이트 판정과 다르다` | `pctcs.ini` 의 `FITS_TelID` 가 다르다. **서로 다른 값마다 한 번씩만** 뜨므로, 조용해졌다고 해결된 것은 아니다 | 어느 쪽이 잘못 배포됐는지 확인. 파일명은 우리 판정을 따른다 |
| `TC 가 TELID=KMTN 을 보냈다` | pctcs 의 `FITS_TELID` 가 **미설정 기본값**이다 | `pctcs.ini` 의 `FITS_TELID` 를 채운다. 우리 파일명에는 영향 없다 |
| `사이트 … 의 측지값이 없다` | `[site.<코드>]` 가 비어 있다 | 좌표가 sentinel 로 실린다. ini 를 채운다 |

## 사이트를 옮겨 배포할 때

**`[node] observatory` 한 줄만 고친다.** 사이트 코드·좌표·경계·파일명·`ORIGIN`·`INSTRUME`·`TELESCOP`·`FPAID` 가 전부 따라온다 — `[site.ctio]`/`[site.saao]`/`[site.sso]`/`[site.kasi]` 가 ini 안에 다 들어 있다.

적는 값이 **그대로 `OBSERVAT` 카드**가 된다 (`CTIO`/`SSO`/`SAAO`/`KASI`). 그래서 ini 를 보면 헤더에 무엇이 실릴지 그대로 보인다.

그 다음 **한 번 띄워 배너를 확인한다.** 값이 틀리면 기동이 아예 멈추고, 값은 맞는데 자리가 틀리면(관측소에서 `KASI` 로 둔 경우) 실물 백엔드에서 경고가 뜬다.

## 사이트 판별은 설정 한 줄이다 (D-020, D-015 대체)

**호스트 IP 판정은 D-020 이 대체했다** (운영자 확정 2026-08-24, DevNote 11.27). `siteid.py` 와 `site_from_ip` 는 지웠으니 **되살리지 말 것.**

두 위험 중 하나를 고른 결과다 — D-015 는 "잘못 배포된 ini" 를 막으려 했지만, **NIC 이 내려가거나 낯선 대역에 붙으면 진짜 관측 자료가 실험실 이름으로 저장되는** 반대 위험을 안고 있었다. 운영자가 **설정 쪽**을 택했고, 대신 그 값이 틀리면 **기동이 멈추게** 했다.

> ⚠️ **그래서 배포 절차가 이 문서의 유일한 방어다.** 판정이 대신 잡아 주지 않는다. 기동 배너를 읽는 것을 건너뛰지 말 것.
