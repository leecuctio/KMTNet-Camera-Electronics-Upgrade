# gmon 확장 로드맵 — 대형 천문대·자율관측 시스템 벤치마킹 제안

작성: 2026-08-29 · 상태: **제안** (팀 검토 후 채택 항목을 `project_management/planning/BACKLOG.md`에 등록)

## 배경과 방법

gmon v2는 현재 **시상 모니터링**(4방위 FWHM·PSF 스냅샷·시계열 그래프)과
**온도 기반 개루프 초점 보정**(`ref = slope×T − (base+dfocus)`)을 제공한다.
이 문서는 대형 천문대·로봇 서베이(Rubin, ZTF, DECam/DES, HSC, LCO, GOTO,
ASAS-SN, OGLE/MOA 등)가 같은 자리 주변에 붙여 쓰는 기능들을 5개 도메인
(폐루프 제어 / 영상 품질 메트릭 / 운영 자동화 / 사이트 장기 통계 / 동급
서베이 벤치마킹)으로 나눠 조사하고, KMTNet 제약 — 가이드칩 하드웨어
(CCD47-20 4칩, 0.52″/px), TCS 구동 수단(fttgoto/dtilt뿐), 서베이 포인팅,
소수 인력 유지보수 — 으로 실현성을 걸러 우선순위를 매긴 결과다.
수집 30건 → 병합·검증 후 **18건 채택, 2건 제외**.

핵심 관찰: gmon은 이미 매 노출 sex 카탈로그·psfex 산출물·TCS 텔레메트리를
만들고 버린다. P1~P2의 다수는 **새 측정 없이 이미 흘러가는 데이터에서
추출·기록·판단만 추가**하는 것들이다.

## P1 — SSO 커미셔닝 전후 바로

### 임계값 경보 데몬 (galert)  `M (수주)`

fw 시계열·파이프라인 결과·TCS 응답을 규칙 기반으로 감시해 Slack 웹훅/이메일로 통지하는 단일 데몬. 규칙: fwAVG 급등(직전 1시간 중앙값 대비), 한 칩만 지속 열화, TEMP(ENS3) 동결, FOCUS 안전범위 이탈, 파이프라인 연속 실패, TCS auxstatus 무응답. 쿨다운·중복 억제·주간 자동 해제 포함.

- **선례**: Rubin Observatory Watcher CSC — 텔레메트리 구독 규칙 기반 알람을 LOVE 운영 화면·통지 채널로 라우팅. ASAS-SN 무인 유닛 장애 원격 자동 통지.
- **gmon 적용**: 검증됨: (a) 신규 측정 없음 — run/data/fw*.dat tail 폴링(§5.2 형식 실재 확인), result.*.json chips.*.ok, gtcs auxstatus timeout_sec 헬스체크 재사용. (b) 구동 없음(읽기 전용). (d) 표준 라이브러리(urllib+smtplib)만으로 구현, gmon.conf [alert] 섹션 신설 — 의존성 제로.
- **가치**: 무인 3사이트에서 시상 급락·초점 이탈·센서 고착을 사람이 그래프를 안 봐도 수 분 내 인지 — 소수 인력 야간 커버의 핵심 공백을 메운다.
- **주의**: 임계값은 수년치 fw 이력으로 백테스트 후 설정. 과학 CCD 읽기 중 가이드 노출 공백을 '파이프라인 정지'로 오인하지 않도록 프레임 도착 주기 기반 유예시간 필수.
- **우선순위 근거**: 무인 원격 운영 전환의 전제 조건이므로 SSO 커미셔닝과 동시에 가동돼야 이후 모든 자동화의 안전망이 된다.

### 상태 페이지·하트비트 (gstatus)  `S (수일)`

30초 주기로 run/status.json + 정적 status.html 생성: 최신 프레임 도착 경과, fw 마지막 줄(fwAVG·FOCUS·TEMP)과 나이, 데몬 pid 생존, TCS 마지막 응답, 디스크 여유, dry_run 상태. 3사이트 JSON을 본원 rsync로 모아 KASI 통합 한 페이지.

- **선례**: LCO 사이트별 망원경 가용 상태 웹 페이지(원격 운영 1차 화면), ASAS-SN 유닛별 상태 웹 노출.
- **gmon 적용**: 검증됨: 원천이 전부 파일로 실재 — run/pid/, run/data/fw*.dat, run/incoming·processed mtime, gtcs auxstatus, [ics] dry_run(gmon.conf에서 확인). 새 측정 없이 표준 라이브러리 200줄 수준.
- **가치**: '지금 SSO/CTIO/SAAO가 정상인가'를 5초 만에 판단, galert가 참조할 하트비트 파일 겸용.
- **주의**: 내부망 전용 운용, 외부 공개 시 접근 제어. gstatus 자체의 정지는 galert 하트비트 규칙으로 상호 감시.
- **우선순위 근거**: S급 비용으로 커미셔닝 직후 원격 운영 화면을 즉시 제공하며 galert와 상호 보완이라 함께 넣어야 효과가 난다.

### systemd 워치독·자동 재시작 (데몬화)  `S (수일)`

gwatch·galert·gstatus 데몬을 systemd 유닛으로 등록, Restart=on-failure + WatchdogSec/sd_notify로 사망·행업 모두 자동 재기동. GUI(gmon.py)는 제외.

- **선례**: Rubin CSC의 liveness probe 자동 재시작과 동일 원리의 소규모 표준 관행(systemd 워치독). GOTO pilot의 하위 데몬 감시·재시작 구조(확신도 중간).
- **gmon 적용**: 검증됨: gwatch.py 폴링 루프에 WATCHDOG=1 datagram 한 줄 추가(sd_notify는 소켓 쓰기라 표준 라이브러리로 가능), gcommon.Pidfile 경로 그대로 유닛에 사용. 유닛 파일 3~4개 + 설치 절차.
- **가치**: 원격 사이트에서 데몬 사망·NFS 행업 시 ssh 수동 재기동을 없애고, journald에 장애 이력이 공짜로 남는다.
- **주의**: Tk GUI의 초점 AUTO 루프는 워치독 사각지대 — 장기적으로 AUTO 루프를 gwatch 쪽으로 이관하는 후속 결정 필요. systemd 없는 구형 OS면 cron+pidfile 폴백.
- **우선순위 근거**: 커미셔닝 배포 시점에 유닛을 함께 설치하는 것이 가장 싸고, P1 데몬들(galert/gstatus)의 생존을 보장하는 기반이다.

### 설정·보정상수 변경 이력 저널 (config journal)  `S (수일)`

gmon.conf·run/dfocus.txt 변경을 시각·호스트·이전값→새값으로 append-only 저널에 자동 기록, 데몬 기동 시 gmon.conf sha256을 직전 사본과 비교해 diff를 로그·상태 페이지에 표시. git 자동 커밋은 보류(1단계 텍스트 저널).

- **선례**: Rubin의 ts_config_* git 저장소 기반 설정 버전 관리. KMTNet 자체의 base 개정 이력(4.7→4.145→5.56)이 주석으로만 남는 실증적 문제.
- **gmon 적용**: 검증됨: dfocus 변경은 gcommon.write_dfocus() 단일 경로(GUI ±버튼 포함)라 저널 한 줄 추가가 전부. gmon.conf 해시 비교는 load_config()에 삽입. DESIGN.md §11 운용판 파리티 표가 보여주는 사이트별 상수 드리프트를 가시화.
- **가치**: '언제 base를 바꿨더니 그 뒤로 초점이 나빠졌다' 추적을 즉시 가능하게 하고 3사이트 설정의 조용한 분기를 드러낸다.
- **주의**: 저널 파일은 gjanitor 영구 보존 목록에 포함할 것. git 자동 커밋은 충돌 부담으로 1단계 제외.
- **우선순위 근거**: 커미셔닝 기간이 상수 변경이 가장 잦은 시기라 그 전에 기록이 시작돼야 이후 재적합·사이트 비교의 근거 데이터가 남는다.

### PSF 타원율·방향각 모니터 (whisker 진단)  `S (수일)`

[병합: 타원율 지도 모니터 + 추세 모니터 + 시계열·경보 3건] sex 카탈로그의 ELONGATION에 THETA_IMAGE를 추가해 칩별 중앙값 e·θ를 노출마다 기록(FLAGS=0·SNR_WIN 컷), 별도 run/data/el*.dat + gplot 패널 + 스냅샷 미니 whisker 화살표. 4칩 θ 일제 정렬=추적/바람, 방위별 방사·접선 패턴=틸트/정렬, 대칭 열화=디포커스로 원인 분류. 임계 초과는 galert 규칙으로 연동. 진단 전용 — 자동 구동에는 쓰지 않음.

- **선례**: DES/HSC의 PSF whisker plot 표준 QA + DECam 커미셔닝 정렬 검증(최강 선례), Subaru HSC 온사이트 QA(Furusawa), Rubin RubinTV 노출별 타원율, LCO TelOps 프레임별 FWHM·타원율 시계열.
- **gmon 적용**: 검증됨: config/default.param.psfex에 ELONGATION이 이미 있음(파일 확인) — THETA_IMAGE 한 줄 추가. gpsf.py가 이미 astropy fits로 카탈로그를 다루므로 노출당 수 ms. fw*.dat는 §5.2 운용판 호환 계약이라 불변, 별도 el*.dat 채택. (a) 0.52″/px 언더샘플링은 중앙값·평활로 대응 가능.
- **가치**: FWHM 하나로 구분 못 하는 '왜 나쁜가'(초점 vs 틸트 vs 추적 vs 바람)를 원격에서 스냅샷 한 장으로 판독 — 구현 비용 대비 진단력 향상 최대 항목.
- **주의**: 개별 별 타원율은 언더샘플링 노이즈가 크므로 노출당 중앙값·이동 중앙값으로만 판단. 방향각 통계는 원형 통계(2θ 평균) 필수, 최소 검출 수 조건.

### 투과율/구름 지수 (검출 수 + 밝은 별 플럭스 + 배경)  `M (수주)`

[병합: 별 개수·플럭스 투과율 감지 + 투명도 지수 2건] 노출마다 칩별 검출 수와 포화 직전 밝은 별 부분집합의 중앙 기기등급을 기록, 같은 벌지 필드의 직전 방문 대비 상대 편차로 구름 판정·경보(서베이의 필드 반복 방문이 기준선을 자연 축적). 동시에 이 지수를 초점 AUTO·재초점 트리거의 가드로 사용해 구름 부푼 FWHM에 초점 로직이 오반응하지 않게 함. 심화: 밝은 별 Gaia 대조 근사 영점.

- **선례**: CFHT SkyProbe(Cuillandre et al.) 실시간 대기 감쇠 측정, ATLAS의 카탈로그 매칭 영점 기반 구름·소광 정량화(Tonry et al. 2018), ZTF의 PS1 대비 실시간 영점 비측광 플래그.
- **gmon 적용**: 검증됨: FLUX_APER(1)·FLUXERR_APER(1)이 default.param.psfex에 이미 있음(파일 확인) — 추출·집계만 추가. 필드 식별은 tcsstatus RA/DEC(고정 격자). 필드별 롤링 기준선은 fw류 텍스트 이력 패턴 재사용. make_synthetic 미광·산포 옵션으로 임계 오프라인 튜닝.
- **가치**: 전천 카메라 없이 노출 데이터만으로 구름 유입을 수 분 내 감지해 '시상 나쁨 vs 구름'을 원격 구분 — 관측 지속/중단 판단과 초점 자동화 오동작 방지의 이중 효과.
- **주의**: 벌지 극심 혼잡으로 검출 수가 시상에도 민감 — 검출 수·플럭스 편차 병용, 절대 임계 금지(같은 필드 상대 변화만). 필드 경계·포인팅 미세 차이의 기준선 오염 주의.
- **우선순위 근거**: 초점 자동화(P1·P2)의 오동작을 막는 가드이자 galert의 구름 규칙 입력이라 그들 직후 올해 안이 적기다.

### 노출 품질 지수 t_eff + 한계등급  `S (수일)`

이미 측정 중인 FWHM·배경(·투과율 지수 구현 후 η)을 결합해 DES식 t_eff = η²×(FWHM_기준/FWHM)²×(b_dark/b)와 5σ 한계등급을 노출마다 계산·기록, 임계 미달 노출 플래그. η는 투과율 지수 전까지 1로 시작.

- **선례**: DES t_eff(Neilsen et al.) 준실시간 계산·임계 미달 자동 재큐잉(obstac), Rubin 동일 개념 채택, ZTF 영상별 maglim 산출·운영 활용.
- **gmon 적용**: 검증됨: 완전 파생 계산 — fw*.dat의 fwhm·배경 sd·SECZ와 default.sex MAG_ZEROPOINT·GAIN·pixel_scale만 사용, 신규 측정 0. gpsf 끝단 컬럼 2개+gplot 패널. 수년치 이력 소급 적용으로 사이트별 t_eff 기준 분포 즉시 확보.
- **가치**: 여러 지표를 스칼라 하나로 압축해 소수 인력이 밤 품질을 한눈에 판단, 마이크로렌징 파이프라인에 품질 미달 노출 목록 자동 제공.
- **주의**: 절대 한계등급은 영점 캘리브레이션 전까지 근사. 기준 FWHM·b_dark는 사이트별 이력 분포에서 정의할 것.
- **우선순위 근거**: 배경·투과율 항목이 갖춰지면 계산식 하나라 거의 공짜로 따라오는 마무리 항목이다.

### 장기 시상 통계 DB + 월간 3사이트 비교  `S (수일)`

수년치 fw 이력(+el·env 파일)을 사이트 태그와 함께 단일 SQLite(또는 연도별 CSV)로 적재하는 ingest 스크립트와, 월별·계절별 FWHM 중앙값/사분위/CDF·천정 환산 시상(×secz^-3/5)을 산출하는 월간 배치. SAAO 이력 tar 일괄 ingest 포함. 돔 시잉·재적합·리포트 분석의 공통 기반 DB.

- **선례**: ESO Paranal ASM의 수십 년 사이트 통계 아카이브, CTIO Tokovinin MASS-DIMM 장기 시잉(KMTNet-CTIO와 같은 능선), CFHT MegaCam delivered IQ 이력으로 돔 벤팅 ~0.1″ 개선 실증.
- **gmon 적용**: 검증됨: fw 한 줄 형식(YY:MM:DD:HH:MM:SS fwN fwE fwW fwS FOCUS TEMP SECZ — DESIGN.md §5.2 확인)과 gplot.py의 구형/신형 시각 자동판별 재사용. [site] name 태깅, 출력은 기존 gnuplot pngcairo. SQLite는 표준 라이브러리라 의존성 없음.
- **가치**: 3기 동일 하드웨어·동일 측정계라는 고유 강점으로 사이트별 계절 기대치와 이상 사이트를 데이터로 식별 — 후속 분석들의 공통 기반.
- **주의**: fw의 FWHM은 대기+돔+광학+초점오차 합산 delivered IQ — DIMM 시잉과 직접 비교 시 해석 주의. fw_time=arrival 구간의 수분 시각 오차, 구형 파일 연도는 파일명 의존.
- **우선순위 근거**: 분석 계열 제안들(돔 시잉·재적합·비교 리포트)의 공통 토대라 올해 안에 만들어야 나머지가 그 위에 선다.

### 돔 시잉 진단 (ENS 전 채널 로깅 + ΔT–FWHM 상관)  `M (수주)`

매 노출 auxstatus의 ENS 전 채널을 밤별 env 파일에 기록하고, 돔내−외기 ΔT 빈별 FWHM 중앙값과 FWHM ∝ ΔT^(6/5) 회귀를 밤/월 단위 자동 산출, 문턱 초과 밤에 '돔 시잉 의심' 플래그. 로깅은 커미셔닝부터 시작, 분석은 DB에 조인해 누적 후 가동.

- **선례**: CFHT Racine et al. 1991 계열 정량화(거울 0.40″/°C^1.2, 돔 ~0.1″/°C^1.2)와 IQIP 돔 벤트 12개로 DIQ ~0.1″ 개선 실증, Tokovinin의 Blanco 돔 시잉 모니터(같은 능선), Keck-II 온도 서미스터 결합 장기 분석.
- **gmon 적용**: 대체로 검증, 한 가지 정정: auxstatus 응답 dict에는 ENS 전 채널이 포함되나 gtcs.header_values는 ENS1..3만 포맷(gtcs.py 확인) — env 기록 경로에 ENS4..7 추가하는 소폭 확장 필요. 어떤 ENS가 돔내/외기인지 [site] ens_inside/ens_outside 매핑은 커미셔닝 체크리스트 항목(사이트별 상이 가능).
- **가치**: '시상 나쁜 밤'의 원인을 대기 vs 돔으로 분리해 환기·야간 개방 절차 같은 저비용 조치의 근거 확보 — 0.1″ 수준 개선도 마이크로렌징 검출 효율에 직결.
- **주의**: ENS 센서 실제 위치·교정 확인 선행 필수. 상시 DIMM 부재로 대기 항은 통계 분리만 가능 — 수십 밤 이상 누적 필요, 성급한 결론 금지.
- **우선순위 근거**: 로깅을 올해 시작해야 내년에 통계가 서므로 기록부는 조기, 분석부는 누적 후로 나눠 P2에 둔다.


## P3 — 장기 검토

### Intra/extra-focal 도넛 진단 (저차 한정 축소판)  `M (수주)`

월간 점검·커미셔닝 전용 진단 모드: fttgoto ±big_step(0.5)급 디포커스로 가이드칩 도넛 영상을 받아 외경에서 부호 있는 디포커스, 4칩 반경 차에서 틸트, 내부 비대칭에서 코마성 정렬 이상만 정량화(파면 재구성 없음)해 진단 PNG 출력. 결과는 dtilt/base 보정 제안으로만.

- **선례**: VST/OmegaCAM의 보조 CCD 2장 곡률 센싱 능동광학(Kuijken 2011 — '가이드급 칩 도넛 분석'의 직접 선례), DECam 도넛 헥사포드 폐루프(Roodman et al. 2014), Rubin AOS 코너 라프트 intra/extra 쌍.
- **gmon 적용**: 검증됨: fttgoto와 big_step=0.5(gmon.conf 확인) 실재, gsplit의 1024×1024 칩 영상에서 numpy 애뉼러스 피팅(sex 불필요), 진단 PNG는 gsnap mpl 백엔드 재사용, make_synthetic에 고리형 PSF 주입 모드 추가로 회귀시험. (a) 0.52″/px에서 0.5 오프셋의 도넛 크기·포화는 하늘 선행 확인 필요.
- **가치**: 일반 스윕이 원리적으로 못 주는 부호 있는 디포커스와 코마 진단을 한 시퀀스로 얻어 커미셔닝·사이트 간 광학 상태 비교의 기준 도구.
- **주의**: 보정 자유도가 초점+2축 틸트뿐이라 그 이상(비점수차 등)은 읽어도 조치 불가 — 진단 범위 엄격 한정. 과학 관측과 병행 불가(전용 시간). 파면 재구성 확장 유혹은 유지보수 부담으로 금지.
- **우선순위 근거**: 행동 가능한 정보의 대부분을 P1 스윕+P2 틸트가 더 단순하게 제공하므로, 온-스카이 타당성 확인 후 여유 시점의 진단 보강용 장기 항목이다.

### 별 위치 기반 추적 드리프트·플렉셔 모니터  `M (수주)`

같은 필드 연속 노출 간 밝은 별 X/Y_IMAGE 최근접 매칭으로 칩별 평균 centroid 이동(dx,dy)을 각도 환산 기록. 4칩 공통 벡터=추적/지향, 칩별 상이=광기계 변형으로 구분. HA/ALT/AZ와 병기해 자세 의존 플렉셔 맵을 이력 회귀. 노출 내 고주파 지터는 타원율 모니터가 대리 지표.

- **선례**: Rubin RubinTV의 노출별 마운트 지터/이미지 모션 산출·플래그(AuxTel부터 운영). DECam 가이더 centroid 활용은 세부 불확실 표기 유지.
- **gmon 적용**: 검증됨: X_IMAGE/Y_IMAGE가 default.param.psfex에 이미 있음(파일 확인) — 직전 노출 카탈로그 1개 추가 보관+단순 매칭(가이딩 중이라 이동 소). 0.52″/px 환산, gplot 패널 추가. tcsstatus HA/ALT/AZ 실재 확인.
- **가치**: 9k 과학 모자이크 별상 끌림의 원인(추적 vs 시상 vs 광학)을 데이터로 특정해 원격 하드웨어 점검 우선순위 결정을 지원.
- **주의**: 노출당 FITS 1장이라 진짜 추적 오차 PSD(고주파)는 원리적으로 불가 — 노출 간 저주파 드리프트 한정임을 명시. 필드 전환 경계에서 매칭 리셋 로직 필요.
- **우선순위 근거**: 진단 가치는 있으나 자동 구동·야간 운영 판단에 직접 쓰이지 않고 타원율 모니터(P1)가 1차 대리 지표를 먼저 제공하므로 장기 항목이다.

## 검토 후 제외

- **바람–타원율 상관 분석 (windshake/돔 난류 진단)** — 호스트 관측소(CTIO/SAAO/SSO) 기상 피드 접근 협의와 사이트별 파서 3벌 상시 유지라는 외부 의존이 '소수 인력·유지보수 단순성' 제약에 정면으로 어긋나고, 결과로 구동할 수단이 없어(fttgoto/dtilt로 바람은 못 잡음 — 방풍 설비 투자의 근거 자료 수준) 상시 기능으로서의 가치가 비용에 못 미친다. 생존 항목인 타원율·방향각 시계열(el*.dat)과 장기 통계 DB가 갖춰지면 필요할 때 기상 자료를 받아 일회성 오프라인 연구로 같은 결론을 얻을 수 있으므로 상시 데몬 채택은 탈락.
- **포인팅 의존(고도/HA) 플렉셔 항 — 독립 기능으로서** — 벌지 위주 서베이는 ALT 범위가 좁아 플렉셔 항이 온도 항과 부분 축퇴할 가능성이 커(제안 스스로 인정), AUTO 루프 계산식을 바꾸는 독립 기능으로 두기엔 근거가 부족하다. 별도 항목이 아니라 '초점 모델 재적합 도구'(P2)의 유의성 검정 선택 항으로 흡수 — 이력 회귀에서 통계적으로 유의할 때만 ref 식에 추가하고, 유의하지 않으면 도입하지 않는 판단을 정식 결과로 인정한다.
